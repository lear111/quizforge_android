## 登录（§7.2）

- 原生 `HubConnection`：PKCE S256，`state` 为 192 位随机数，10 分钟有效，只能使用一次；`client=android`，回调固定为 `quizforge://hub/connect`，origin 固定。授权码由原生 `POST /api/connect/token` 换取。
- 设备令牌用独立的 Android Keystore AES-256-GCM 密钥加密，保存到私有 AtomicFile `hub-connection.enc`。页面拿不到令牌；读不出的文件按“未登录”处理。
- Web 登录窗口调用 `window.open(authorizeUrl)`，“手动打开登录页”和“在题库广场管理设备”两个链接也指向 Hub。Android 预加载脚本（`web/android-hub-links.js`）把这三处转给原生 `hub.browse`，原生只接受固定 origin 的 HTTPS 地址，用 Custom Tabs 打开（直接发送 Custom Tabs 协议的 intent extra，没有新增依赖）。WebView 本身不会加载 Hub 页面；`shouldOverrideUrlLoading` 也会把 Hub 地址交给 Custom Tabs。“获取题库”沿用原来的 `hub.open`。
- 页面的 REST 调用由 `ai-service.js` 转给原生方法：`GET /api/settings/ai` 附带 `hub` 摘要；`GET /api/settings/ai/hub` 返回账号、余额（来自 `/api/connect/me`）和 `manageUrl`；`POST …/hub/login`、`/logout`、`/redeem`。账号请求在单独的网络线程上执行，不占用本地存储队列。401 时清除令牌；退出登录时先删除本地令牌，再尽量通知 Hub。
- 用户中心的文案沿用 Web（包括“这台电脑：”），没有为 Android 改写。

## 评分（§7.2，Web `ai-provider.js`）

- 设置新增 `useOfficial`、`useCustom` 两个字段。旧的已保存设置没有这两个字段时，按 Web 规则视为使用自定义模型（有服务地址时 `useCustom=true`）。可以开启总开关而不选择评分来源；选中自定义模型时必须填写服务地址和模型名。切换来源会更新 `configurationVersion`，已排队但尚未发出的评分请求会停止，与修改模型配置时一致。
- 免费额度请求：`https://quizforge.treenewbee.cloud/api/ai/v1/chat/completions`，模型 `quizforge-official`，Bearer 设备令牌，开启视觉，`json_object`，`stream:false`，`max_tokens` 8192，超时 120 秒。结果记录为 `provider:"quizforge-official"`。
- 错误映射与 Web `classifyOfficial` 一致：401 → `AI_OFFICIAL_LOGIN`（同时清除令牌），402 → `AI_OFFICIAL_BALANCE`，`AI_BUDGET_EXHAUSTED`，429／`AI_BUSY` → `AI_RATE_LIMIT`，502 → `AI_UPSTREAM`，413 → `AI_INPUT_LIMIT`，404／503 → `AI_OFFICIAL_UNAVAILABLE`，其他 → `AI_CONFIG`。网关返回的错误文本不会保留。
- 两个来源都开启时，先用免费额度；遇到登录失效、余额不足、总量用完、服务不可用、上游出错、超时、网络错误或限流时，这次改用自定义模型，并记录实际使用的来源。请求过大或格式错误时不改用自定义模型。未登录时直接跳过免费额度；只开启免费额度且未登录时报 `AI_OFFICIAL_LOGIN`，不会发出请求。
- 模型测试只测试自定义模型。
